# Task: a real intent classifier

Build a learned classifier for instruction understanding, replacing pattern
matching. **Create new files only — do not modify any existing file.**

## Why

`AutonomousSystemController._parse_direct_command` in `main.py` recognises
instructions with a long chain of regexes returning `{"type": "<intent>"}`.
There are **78 intent types**. Roughly 7 in 10 instructions match a rule,
which is fast but does not generalise — an unanticipated phrasing is not
understood and falls through to a language model.

There is already a trained model at `data/neural_command_model.json`. **Do
not extend it.** It is 768→64→5, ~49.5k parameters, and its five labels are
`conversation, file, general, system, web` — it cannot tell "create a task"
from "delete a task", and it is marked `advisory: true` so nothing acts on
it. The problem is the label space, not the layer size.

## Build these four files

### 1. `learning/intent_dataset.py`

Builds a labelled corpus.

Use `_parse_direct_command` as a **labelling oracle**: for any command it
parses, the returned `type` is the gold label.

Seed commands from:
- `benchmark/tasks.py`
- `benchmark/multistep.py`
- `tests/test_intent_matrix.py`
- the `episodes` table in `data/episodic_memory.db` (real user commands)

Then expand with paraphrases generated by the local model (`qwen2.5:3b`,
host in `config/settings.json` under `ollama.host`). Include contractions,
misspellings and spoken-style phrasing — voice transcription is a real
input path here. Label each paraphrase with its seed's intent.

Output `data/intent_corpus.jsonl` as `{"command": ..., "intent": ...}`.
Report per-intent counts and flag any intent with fewer than 20 examples.

### 2. `learning/intent_classifier.py`

Trains and serves the classifier.

Features: embeddings from `nomic-embed-text` (768-dim). `core/embeddings.py`
already wraps this and returns `None` when unavailable — fall back to
character n-grams then, and never crash.

```python
class IntentClassifier:
    def train(self, corpus_path: str) -> dict: ...   # metrics
    def predict(self, command: str) -> dict: ...     # {"intent","confidence","alternatives"}
    def save(self, path: str) -> None: ...
    def load(self, path: str) -> bool: ...           # False if absent, never raise
```

Hold out 20%, stratified by intent. Report overall accuracy, per-intent
precision and recall, and **a calibration table of accuracy against
confidence** — the confidence number has to mean something, because the
wiring will threshold on it.

### 3. `benchmark/intent_eval.py`

Compare three routers on the held-out set:

1. regex only (`_parse_direct_command`; a `None` counts as a miss)
2. classifier only
3. regex, then classifier when the regex misses

Print accuracy and mean latency for each.

**Do not tune anything to make the classifier win.** An honest result
showing the regexes win on covered phrasings while the classifier wins on
unseen ones is the useful outcome, and is what is expected.

### 4. `tests/test_intent_classifier.py`

pytest. Cover:
- `load()` on a missing file returns `False` rather than raising
- `predict()` works when embeddings are unavailable
- confidence is within `[0, 1]`
- training on a tiny fixture corpus works

**Tests must pass on a fresh clone with no trained model present.**

## Constraints

- Dev machine: 7.4 GB RAM, 4 GB VRAM. Nothing may load a model larger than
  `qwen2.5:3b` locally. Training must run on CPU in minutes, not hours.
- Google Colab is available if training needs more, but the corpus builder
  and the classifier must both still run locally.
- Match the existing code style: docstrings explain **why** a thing is the
  way it is, not what the signature already says.
- **Report the real numbers even if they are unflattering.** This codebase
  has a hard rule against claiming success that was not verified — see
  `tests/honesty_audit.py`.

## Acceptance

```bash
python -m pytest tests/test_intent_classifier.py -q   # passes
python learning/intent_dataset.py                     # corpus + per-intent counts
python learning/intent_classifier.py                  # trains, prints held-out metrics
python benchmark/intent_eval.py                       # three-way comparison
```

Do not wire the classifier into the router. That is handled separately.
